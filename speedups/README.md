# LingBot-VLA v2 训练提速（4 卡，全局批量 256）

| 配置 | 秒/步 | 训练损失 |
|---|---|---|
| 基线（微批 16 × 累积 4） | 8.22 | — |
| `OPT_NO_RESHARD_BWD=1` | 7.94 | 24 步与基线逐位相同 |
| 再加 `MUON_OWNER_COMPUTE=1` | 6.22 | 与基线差在第 4 位小数 |
| 再加梯度检查点，微批 32 × 累积 2 | 6.94 | — |
| 再加梯度检查点，微批 64 × 累积 1 | 7.33 | — |

基线一步的构成：反向 3.3 秒，前向 2.5 秒，优化器 1.3 秒，两个蒸馏老师 1.1 秒，等数据 0 秒。

| 文件 | 作用 |
|---|---|
| `patch_opt.py` | 给官方代码打补丁，三个开关默认全关：`LINGBOT_STEP_TIMING`（分步计时）、`OPT_NO_RESHARD_BWD`（梯度累积的微批之间不重新切分 FSDP2 参数）、`MUON_OWNER_COMPUTE`（Muon 的每个矩阵只在一张卡上做 Newton–Schulz，两次 bf16 all_to_all 交换） |
| `sim_owner.py` | 单进程模拟多卡，核对上一项的索引逻辑与原算法一致 |
| `an_opt.py` | 汇总各次测试的计时和逐步损失对比 |
| `teacher_cache.py`、`patch_cache.py`、`build_teacher_cache.py`、`tc_check.py` | 把两个冻结老师的输出提前算好缓存（按输入图像的像素指纹查找，查不到就回到在线计算） |

老师输出缓存还在做：深度老师的缓存和在线计算逐位一致；视频老师的第一次验证没通过（建缓存时传了帧率参数，而训练时这个参数在数据管线里被丢弃、老师用的是默认值），已改正，待重新验证。

同样的排查在另外两个模型上没有找到不改训练配方的办法：π0.5 在 8 张不支持直连的 RTX 4090 上，一步 5.8 秒里约 3.4 秒是与批量无关的卡间通信；SmolVLA 在 2 张 A40 上显卡已经算满。
